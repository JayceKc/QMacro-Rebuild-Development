| --- | --- |
| L344–351 | 啟動覺醒工作。父流程將工作 ID 存在本地變數，子框架候選呼叫 L573。原 L576 有「覺醒已啟動」日誌。 |
| L353–362 | 啟動死亡監控。父流程將工作 ID 寫到共享變數。子框架候選呼叫 L669，原 L686 有監控啟動日誌。原 L3191 讀相同共享變數，L3193 將其傳給工作控制。 |

兩組父流程重播核對了 ID 的本地與共享寫入，並用各自的死亡監控 ID 重播保留 L3190–3193。道具欄和進本呼叫在兩案均返回。六組獨立子工作案例覆蓋覺醒模式 0／1／2／3 和死亡監控初始化旗標 0／1。覺醒模式 0、2 各走到一個保留的首個找圖位置，模式 1 持續等待，測試以步數上限停止。死亡監控兩案均到 L686，只有旗標為 1 的案例會先走 L685 寫值。

覺醒、死亡監控及進本的原呼叫位址仍缺失。重播採用候選位址和受控 ID，父流程與子工作分開驗證。實際並行時序仍待確認，原缺失值保留。
